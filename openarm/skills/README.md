# OpenArm 动作场景

这里保存机械臂的场景说明、目标点和动作编排，是项目的机器人技能目录，不是 Codex 插件目录。

| 目录 | 场景 | 首个验证目标 |
| --- | --- | --- |
| `paino_skill/` | 弹钢琴 | 单个琴键的靠近、按下、抬起 |
| `drums/` | 架子鼓 | 单个鼓面的准备、击打、回弹 |
| `drawing/` | 绘画 | 单条笔画的落笔、移动、抬笔 |

每个目录包含 `README.md` 和 `scene.example.json`。钢琴已实现独立 MuJoCo 场景和原控制面板接入，使用 paino_skill/start_piano.cmd 启动，详见 paino_skill/README.md；架子鼓和绘画仍为模板。动作序列模板 JSON 不能直接执行。

## 共用约定

- 仿真底座已支持右臂、左臂和双臂同步；动作序列示例仍以右臂单点动作起步。钢琴场景使用左右灵巧手，手指暂时固定；其他场景夹爪保持 home。
- 目标位置单位 m，相对于 `arm_origin`；四元数顺序 wxyz；关节角 rad；时间 s。
- 模板中的 `pose: null` 表示尚未确定目标，不能发送给仿真。目标应来自实际摆放后的场景坐标，不预设未验证的位置。
- 钢琴触点、鼓槌尖端和笔尖属于工具接触点；IK 控制对应臂的 `right_ee_control_point` 或 `left_ee_control_point`。加入工具后，先确定工具相对末端的变换，再转换目标位姿。
- 复用项目官方 IK 和关节空间五次规划器。关节插补不保证工具沿直线运动，也不保证中途无碰撞。
- 默认理想位置伺服：用于检验位姿、动作顺序和可达性，不验证按键力、鼓槌冲击、画笔接触力或真机跟踪精度。

## 后续接入流程

1. 为场景添加独立 MuJoCo 道具文件，复用 V1 机械臂模型，不修改 `vendor`。
2. 确定工具与道具坐标，填入目标位姿；未填完整时禁止执行。
3. 检查目标的 IK、FK 回代误差和整条轨迹的关节限位，并在仿真中检查工具路径。
4. 独立场景控制程序通过现有 `SimClient` 连接本机仿真服务。逐个发送目标，并核对 `motion_id` 和 `COMPLETED` 后推进下一步；停止、失败或连接异常时终止编排。
5. 保存场景参数和验证结果，再扩展多琴键、多鼓面或多笔画。

现有服务使用方法见 [CONTROL.md](../CONTROL.md)。仅使用回环通信，不连接 COM、不发送 CAN。
