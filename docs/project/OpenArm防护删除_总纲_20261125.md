## 0. 一页速览

**场景**：OpenArm 双臂已在工业实验室完成机械固定，由现场操作人员对运动安全负责。用户据此要求删除网页控制台在驱动与控制链路中"阈值略超就拒绝执行、退出控制或自动失能"的防护，只保留通信、协议、机械限位、停止确认、模式切换和本机访问所必需的检查。

**当前基线（2026-11-25）**

| 项 | 数值 |
| --- | --- |
| 永久禁止恢复的 P 项 | **P01～P26**（26 项，全部已清除并回归通过） |
| 仅允许保留的 K 项 | **K01～K12**（12 项） |
| 审计轮次 | 12 轮（2026-11-21 16:22 ～ 2026-11-25 20:48） |
| 最新总判定 | **PASS**（26 PASS / 0 FAIL） |
| 最新测试 | 206 passed / 5 failed（失败均为现场 PCAN 0x51 被占用，与防护无关） |
| 证据文件 | `logs/openarm/audit/` 下 10 个 JSON |

**判定一条新检查是否违规（三步）**

1. 它会**拒绝执行、触发 FAULT、退出控制、自动失能或取消保持**吗？不会 → 不属本体系，正常评审即可。
2. 会 → 属 P01～P26（**FAIL**，重新写入）、属 K01～K12（**PASS**，需说明理由），还是都不属（**UNKNOWN**，登记后请用户裁决）？
3. 属 K07（模式切换前提）但被扩展到运动/使能路径 → 仍判 **FAIL**。

**三条铁律**

- 已删除项**永久禁止**以"安全""防御性编程""最佳实践"为由写回。
- 任何新增阻断必须先取得**用户当次明确授权**，未授权不得实现。
- 发现违规**只报告**，等用户授权后再改；不得顺手"修好"。

## 1. 第一原则（原文）

以下为根目录 [AGENTS.md](../../AGENTS.md) 首节原文，**不得删改、不得加未授权例外**；该节缺失或被改写即判 CRITICAL FAIL。

> ## 第一原则（硬性，优先级最高）：控制链路默认放行，禁止重新写入已清除的防护
>
> 本工作区是已完成机械固定、由现场操作人员负责的工业实验室 OpenArm 场景。控制台、驱动、执行器的默认行为是**放行并继续执行**，不是"阈值略超就拒绝、FAULT、退出控制或自动失能"。
>
> 1. **永久禁止重新引入**以下非必要运动阈值防护，包括但不限于：跟踪误差、路径点/终点偏差、控制周期迟到、反馈速度、力矩、温度、相对行程、反馈年龄、非指令轴偏移、预览后起姿漂移、所需速度/加速度超过某百分比、静止/零位使能前提、MIT 超量程拒绝、预览有效期。
> 2. 任何**新增**会拒绝执行、触发 FAULT、退出控制、自动失能或取消保持的检查，必须先向用户说明并取得**当次明确授权**；未授权不得实现，不得以"安全""防御性编程""最佳实践"为由自行添加或恢复。
> 3. 用户已明确要求删除的防护，代码、测试、文档、交接 Prompt 都不得再写回；发现重新引入按缺陷处理，立即删除并记录。
> 4. 仅保留以下非运动阈值类检查，详见 [OpenArm 防护删除总纲](docs/project/OpenArm防护删除_总纲_20261125.md) 第 2 章：
>    - 关节位置限位、NaN/非数值、映射版本与协议帧格式；
>    - CAN 通道租约、总线状态、反馈/参数超时；
>    - 停止后的逐轴失能回读与"停止未确认"；
>    - 电机模式切换的静止失能前提、固件/模式回读与失败回退；
>    - 完整 C02 盘点与现场协议配置的准入条件；
>    - 本机 Host/Origin/客户端令牌、操控页心跳停止；
>    - 独立 CLI 的 `openarm_trajectory.preflight`（不在网页路径，保留给其他调用方）。
> 5. 现场安全条件变化时，只能由用户明确指示调整；代理不得自行恢复防护、不得用"保护现场"为由改写本原则。
> 6. 本原则适用于 `apps/`、`monitor-ui/`、`configs/`、相关测试和所有交接文档；`openarm/` 纯仿真入口另有其规则，但不得借其恢复控制链路的防护。

> 注：AGENTS.md 第 4 条已直接指向本总纲第 2 章（现行 P01～P26 / K01～K12）。

## 2. 防护项清单

范围：`monitor-ui/` → `apps/openarm_monitor.py` → `apps/openarm_monitor_motion.py` / `apps/openarm_monitor_modes.py` → `apps/openarm_execution.py` / `apps/openarm_driver.py` → `apps/drive_openarm_from_sim.py` 的 `execute()`。网页模式为 `virtual` 时未连接实机、未读写 CAN。

### 2.2 仅允许保留（K01～K12）

这些**不是**运动阈值保护；删除会破坏协议正确性、通信闭环或用户明确要求的停止语义。

| 编号 | 位置 | 保留内容 | 理由 |
| --- | --- | --- | --- |
| K01 | `MotionPlanner._check_pose`、`openarm_position_mode.encode_target`、`openarm_joint_mapping.finite` | 关节位置限位、NaN/非数值拒绝 | 机械限位与坐标有效性；越界目标没有可执行的物理含义。限位比较带 `LIMIT_TOLERANCE`（5e-4 rad ≈0.029°，约两个编码器步）：贴死限位时反馈会读出 0° 以下一个计数（J4 下限正好是 0°），该量化读数不再被当成越界；超出容差仍拒绝，并在消息中给出本次实际角度 |
| K02 | `PcanBus.send`、`decode_feedback`、`encode_mit` | CAN 帧 ID/长度、反馈帧格式、协议字段编码 | 帧格式错误时驱动器不会执行，继续发送无意义 |
| K03 | `PcanBus.open/status`、`query_motor`、`read_parameter` | 通道租约、总线状态、反馈/参数超时 | 通信不可用时无法闭环控制；属通信故障而非阈值退出 |
| K04 | `Monitor._feedback_view`、`_idle` | 反馈齐全与 `FEEDBACK_AGE=.75 s` 新鲜度 | 不能拿过期反馈规划起点；保留 UI 与预览的必要输入 |
| K05 | `OperatorWatch` / `HEARTBEAT_TIMEOUT=3 s` | 操控页失联超 3 秒触发停止 | 用户已明确保留的失联停止行为 |
| K06 | `PcanTransport.stop`、`Monitor._hardware_run.require_disabled` | 停止后逐轴失能回读；失败保留 `STOP_UNCONFIRMED` | 用户明确要求"停止未确认"可见；属停止确认，不是运动阈值 |
| K07 | `ModeRegisters.require_stationary`、`read_modes`、`switch` | 切模式要求 14 轴静止失能、固件/模式回读、部分失败回退 | 模式寄存器写入的现场协议要求；**只限模式切换路径，扩展到运动/使能即 FAIL** |
| K08 | `ModeRegisters.__init__` / `DriveProfile.__init__` | 完整 C02 盘点、14 轴身份/通道/版本；用 `DriveProfile` 时另需失能预装与易失写入确认 | 模式寄存器写入的配置完整性准入，不是运行阈值；不约束非 MIT 模式的使能和运动（P20） |
| K09 | `Monitor.start_motion` | 预览归属、请求 ID、revision | 防止重复执行和串页执行；不是跟踪误差保护。预览有效期已删除（P19） |
| K10 | `Journal.record` | 日志写入失败即停止（`journal.error` 锁定运动） | 保留可追溯证据；未将其视为"阈值保护"删除 |
| K11 | `create_server` 的校验 | 仅 127.0.0.1、Host/Origin、客户端令牌、JSON 大小/类型 | 本机页面访问控制，与运动阈值无关 |
| K12 | `openarm_trajectory.preflight` | 独立 CLI 的请求版本/时间/起点/速度/加速度预检 | **不在网页路径**：网页由 `MotionPlanner._validate` 直接生成轨迹。保留它是为了不改变 `drive_openarm_from_sim.py` 其他调用方的既有语义 |

## 3. 网页路径的实际效果与验证证据

### 3.1 实际操作表现

- **全部使能**：不再要求先静止/失能；14 轴按当前角度进入保持，计数来自反馈。可在已有角度（包括 J4≈90°）上直接使能。
- **起始位/0位/回0/钢琴原位/逆方向返回**：14 轴反馈齐全即可执行，计划自身使能全部 14 轴，不要求先点"全部使能"。
- **关节/IK 目标**：不再因速度/加速度百分比、模型接触、预览后起姿漂移拒绝；预览不再 60 秒失效；目标仍受关节位置限位约束。
- **执行中**：跟踪误差、路径点/终点偏差、周期迟到、温度、速度/力矩、相对行程、非指令轴偏移只写日志，不触发 FAULT、不失能、不退出 `HOLDING_TARGET`。
- **非 MIT 位置模式**：POS_VEL / VEL / POS_FORCE 与 MIT 一样可直接"全部使能"、预览、执行和保持。目标速度或电流比例超协议量程时按端点饱和并记录提示。
- **特殊帧寻址**：四种模式默认发往基础电机 ID，只有目标帧使用模式偏移（POS_VEL `+0x100`、VEL `+0x200`、POS_FORCE `+0x300`），与 OpenArm 官方 CAN 库一致。
- **停止**：仍走"停止请求→逐轴失能→回读确认"；回读失败保留"停止未确认"。
- **模式切换**：仍要求 14 轴静止且失能，并通过协议配置逐轴读回。
- **试弹/演奏**：手部不可用、谱面缺分指/腕位、换腕与按住重叠、音组无共同腕位时只跳过该组，机械臂继续；实机全曲可直接演奏。
