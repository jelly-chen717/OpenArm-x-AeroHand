## 1. 项目目标与交付范围

连接 OpenArm 双机械臂与机械手，导入 MIDI 文件，解析音符与节奏，生成琴键、手指、琴位和机械臂轨迹之间的映射，实现仿真弹奏、网页音游展示、上位机控制，并逐步完成实物演示。

| 系统 | 功能 |
| --- | --- |
| 联合物理仿真 | 显示并控制 OpenArm 双臂、机械手和可下压复位的琴键 |
| 钢琴可视化网站 | 音符向键盘下落、时值显示、左右手区分、进度与触键状态展示 |
| 上位机 | MIDI 导入与曲目选择、倍率设置、规划预览、播放/暂停/停止、参数和状态管理 |

21 天的优先交付目标是：完成选定曲目的低速实物演示，并有可重复验证的仿真与控制链路。任意 MIDI、完整复杂和弦、高速演奏不作为首版承诺。

核心链路：

```text
MIDI → 音符与节奏 → 实际琴键映射 → 手指/琴位分配
     → 指尖目标与逆运动学 → 平滑关节轨迹
     → 仿真或实物执行 → 触键反馈与网页显示
```

## 5. 建议架构与软件选择

优先方案：Windows + Python + MuJoCo，复用现有 MIDI 解析和上位机，网页独立展示。真实 OpenArm 控制环境根据官方驱动、系统和硬件版本另行确认。

| 层级 | 建议实现 | 说明 |
| --- | --- | --- |
| 输入 | 现有 MIDI 解析模块；必要时使用 mido/pretty_midi | 正确处理多轨、速度变化和音符结束事件 |
| 规划 | Python 离线规划 | 手指分配、琴位选择、IK、轨迹与可执行性检查 |
| 仿真 | MuJoCo Python | 机器人、手指和琴键物理接触 |
| 上位机 | 扩展现有 Python GUI | 首版不同时重写控制软件 |
| 网页 | Vue 3/TypeScript，Canvas 或 PixiJS | 技术候选，开发前按工作量选定 |
| 通信 | FastAPI + WebSocket | 统一命令、状态、时钟与执行反馈 |
| 实物适配 | OpenArm 驱动与机械手独立驱动 | ROS 2/MoveIt 2 是否采用及发行版待兼容性核查 |

RViz 可用于机器人状态和轨迹显示，不提供琴键接触物理仿真。MoveIt 2 可辅助可达性和碰撞规划，不能代替 MuJoCo 的触键物理验证。Isaac Sim/Isaac Lab、Gazebo 暂作备选，首阶段避免同时维护多个仿真平台。

```text
歌曲库 → MIDI解析 → 统一演奏计划 → 调度器
                                  ├─ 仿真适配器 → MuJoCo
                                  ├─ 实物适配器 → 双臂与机械手
                                  └─ 状态服务 → 上位机/网页
```

接口共用不代表控制增益、零位、负载参数或仿真轨迹可以无校验复制到实物。

## 6. 建模与场景任务

### 6.1 双臂

- 确认硬件版本、基座安装位置、关节命名、转向、零位、限位和工作空间。
- 使用匹配版本的官方模型，记录采用的提交或发布版本。
- 验证双臂可显示、接受关节目标并返回实际仿真状态。
- 明确末端法兰、机械手挂载变换和工具负载。

### 6.2 机械手与五指适配

- 确认两只手的型号、左右手结构、自由度、耦合关系和独立控制能力。
- 先检查原始 CAD，保留小指间距；评估拇指长度修改的范围和方向。
- 同时验证拇指对键位的可达性、按压方向、与其余手指的碰撞、活动行程和传动力要求。
- 拇指长度不按白键中心距直接确定，应由安装姿态、关节运动和指尖接触点共同决定。
- 若采用指尖延长件，检查连接刚度、质量、力臂和可拆装性。
- 导出视觉几何，并建立关节、惯量、限位、执行器和简化碰撞体。
- 为每个指尖定义 TCP；结构修改后重新标定，不沿用旧指尖坐标。

导入 STL/OBJ 只能提供几何外形，不等于获得可运动的机械手模型。五指目标也不等于任意五音和弦均可执行。

### 6.3 琴键

建立琴体和独立黑白键，包含运动自由度、复位、行程限位、碰撞与触发状态。按键应发生可观测位移，不能仅靠高亮代替物理触键。

需测量：白键宽度/中心距、黑键宽度/中心、黑白键前后位置及高度差、下压行程、有效触发条件和琴体固定位置。

键盘映射至少记录：物理键编号、MIDI 编号、键型、局部坐标、接触高度、按压方向、行程与触发阈值。不能把全部半音键按等间距 X 坐标排列。

初期可简化为弹性复位关节与键程阈值触发，并设置按下/释放不同阈值避免抖动；该触发逻辑需要与真实电子琴另行对照。

## 7. MIDI、规划与执行规则

### 7.1 解析与倍率

统一事件至少包含音符编号、轨道/通道、开始时间、结束或持续时间、力度、分配的机械臂、手指和琴位。保留源时间与计划执行时间，便于解释降速或延迟。

定义速度倍率 S，则新时间 = 原始时间 / S：50% 为原时长两倍，100% 不变，200% 为原时长一半。开始时间和时值一致缩放，并正确处理 MIDI 变速事件。

导入后先检查音域、同音重叠、复音、持续音、跨区移动和执行能力。延音踏板等首版不支持的事件需明确报告。MP3/WAV 转 MIDI 不纳入首版核心任务。

软件选项允许某倍率，不代表机器人能执行该倍率。规划结果显示请求速度与实际可执行速度；拒绝或建议整体降速，不能默默改变局部节奏或超限运行。

### 7.2 坐标、琴位与手指

- 建立钢琴坐标系：X 沿键盘，Y 沿前后，Z 垂直琴面。
- 标定琴体到机器人基座的刚体变换，以及法兰到机械手和各指尖的变换。
- 初期固定左右臂区域，最终分界由可达性和碰撞验证确定，不默认各负责 16 键。
- 机械臂负责换琴位，手指负责局部弹奏，尽量减少整臂频繁启停。
- 导入后离线生成整首计划；重复目标可缓存 IK 解，但需校验连续性和关节分支。
- 缓存失效条件包括琴体位置、TCP、结构、基座或标定改变。

### 7.3 动作与时间约束

动作分为 PREPARE（准备）、PRESS（按下）、HOLD（保持）、RELEASE（释放），换位还需包含抬升、移动与稳定时间。

提前规划下一目标；提前计算不等于可以在手指仍压键时移动手掌。换位需保证释放与净空，检查双臂、手指、琴体及固定件之间的碰撞。

优先级：单音旋律 → 双臂分区 → 经验证的有限和弦。不能只根据手指数量判断和弦可执行。

轨迹采用平滑插值，考虑速度、加速度和必要的加加速度限制。按压深度、抬指高度、稳定时间受实际结构与节奏共同约束。

## 8. 上位机与网页任务

### 8.1 上位机

| 优先级 | 功能 |
| --- | --- |
| P0 | 导入/选择 MIDI、显示支持范围、请求倍率与可执行倍率、计划预览 |
| P0 | 播放、暂停、停止、执行模式显示和状态反馈 |
| P0 | 按压深度、抬指高度等参数配置及边界检查 |
| P0 | 回零/复位/使能入口按实际驱动能力接入，实物条件未满足时阻止执行 |
| P1 | 琴键/TCP 标定、关节目标与实际状态、日志和失败原因 |
| P2 | 手指分配编辑、复杂和弦、更广曲目兼容 |

按键保持时间以 MIDI 时值和运动约束为基础，不用固定保持时间覆盖整首歌。播放中对结构和关键参数的修改应锁定或要求重新规划。

暂停必须定义机械行为：释放已按下手指、停止未来调度并记录位置；恢复时重新准备并同步时间轴，不能只冻结计时器。停止、窗口关闭、通信异常需有可测试的清理行为；软件停止不能替代物理急停。

### 8.2 音游网页

- 顶部显示曲名、进度、倍率、模式和连接状态。
- 中部显示下落音符，长度对应时值，颜色区分左右臂。
- 底部键盘与最终实物映射一致；按当前音域应为 36 键，待实物核对。
- 调度器提供统一时间基准；网页按时间计算动画，不累计依赖消息到达间隔。
- 下落音符表示计划，实际琴键高亮优先使用仿真触发或实物反馈。
- 没有触键反馈时明确显示为计划/指令状态，不声称实际按键成功。
- 处理暂停、停止、重连和延迟；音频预览与机器人实际琴声状态区分。

## 9. 实物落地与控制策略

### 9.1 定位与校准

优先固定基座和琴体，使用定位治具减少重复摆放误差。示教左右及中间等参考点，建立琴体平面和朝向，结合实测几何生成键位，并用独立键位检查误差。

三点标定不能消除机械臂柔顺、零位或运动学误差；需要时增加局部补偿。视觉标记可作后续辅助，首版不强制引入视觉识别。

### 9.2 位置控制与振动

用户提出位置控制、降低速度以提高精度和平稳性。建议使用关节位置轨迹、必要的重力/负载补偿和实际关节误差监测；具体控制模式及接口以实际型号和官方驱动为准。

位置控制本身不保证指尖精度。还需考虑工具质量和质心、关节间隙、下垂、零点、装配误差、TCP 和琴体位置。执行器报告成功不能替代实际到位或触键验证。

降低振动的实施顺序：减少整臂换位 → 检查基座/法兰/腕部连接刚度 → 限制速度加速度 → 平滑轨迹 → 预留实测稳定时间 → 在误差和电机状态监测下调整控制参数。

### 9.3 触键反馈

确认电子琴是否提供 USB MIDI 输出。若可用，可用于对照实际 note_on/note_off 与计划音符；仍需检查设备延迟及其他消息来源。若不支持，再选择键程传感器、视频人工标注等验证方法。

首轮从空载、单关节、悬空定位到单键逐级验证。进行负载、方向、限位和停止检查后才扩展连续演奏与双臂。

## 11. 验收指标与验证记录

以下为建议目标，未经实测，不能作为当前性能结论：

| 项目 | Day 10 仿真目标 | Day 21 实物目标 |
| --- | --- | --- |
| MIDI | 支持范围内解析正确，报告不支持事件 | 同一演奏计划可追溯 |
| 映射 | 最终物理键数与 MIDI 配置一致 | 完成键位标定并记录可达/不可达键 |
| 单键 | 接触、下压、触发、复位闭环 | 重复触键成功率目标 ≥95%，按明确次数与条件测量 |
| 曲目 | 短单旋律与双臂分区通过 | 选定曲目以可执行低速完成，初始尝试 50%～75% |
| 同步 | 共享时间基准，区分计划/实际事件 | 记录触键延迟、漏按、误按、重复触发和释放异常 |
| 控制 | 播放/暂停/停止及连接状态可验证 | 低速动作、限位、停止与物理急停按实际系统验证 |

定位误差、振动稳定时间、网页延迟和连续演奏次数的具体阈值待首轮测量后冻结。建议每个代表性键先做不少于 20 次重复，记录样本数与条件；不能用少量成功案例推断全键盘成功率。

每次验证记录：软件版本、模型版本、标定配置、曲目、请求/实际速度、实验次数、计划/实际时间、错漏音、振动表现、失败原因与处理。自动测试、离线模拟、物理仿真、用户历史验收和本次实测分别标注。
