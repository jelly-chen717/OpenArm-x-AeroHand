## 电机角度到模型角度的符号核查

`configs/openarm_joint_mapping.json` 当前14轴全部为 `direction=+1, scale=1, p_ref=0, q_ref=0`，所以当前代码关系为 `q_model = p_motor`。这是已保存并确认的映射，本次未修改标定。

调用链：

1. `apps/openarm_joint_mapping.py:39` 将电机反馈换算为模型角度；`:42` 做逆换算。
2. `apps/drive_openarm_from_sim.py` 的 `targets` 调用 `to_motor()` 形成发送角度。
3. `apps/openarm_execution.py` 的 `command()` 校验后将p、v原样传给驱动。
4. `apps/openarm_driver.py:327` 的 `command_mit()` 调用 `encode_mit()`，该链路没有额外按左右臂翻转角度符号。

因此“正增量”的模型方向可用于解释当前映射下的正电机角度；本次结果属于代码与模型核查，不表示重新做了14轴现场独立动作验收。

## 姿态变化后的解释

世界转轴随该轴上游关节旋转。当前姿态的严格表达是：

```text
世界轴 a = 关节所在连杆的世界旋转矩阵 × 模型局部axis
下游点瞬时速度方向 v = a × (点位置 − 关节轴心位置) × 正角速度
```

例如J5已旋转45°后，J6/J7的摆动轴也一起旋转；这时再增加J6/J7可能同时产生前后和左右分量。不能在这种组合姿态下仍直接套用“纯向里/纯向后”。若要核对某次组合运动，应使用该次全部七轴角度计算，而非单看待动轴。

从零位减少角度时，几何趋势与上表相反，但还必须满足关节限位。例如J4零位已处于下限0，不能把反方向解释为允许继续给负角度。
