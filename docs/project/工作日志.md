## 2026-11-22｜J4 贴限位导致 90° 目标被拒的定位与修复

- 现象：现场 8092 `hardware` 控制台输入 J4=90° 被拒，加长运动时间、提高速度上限都无效；拒绝消息只有“左臂/右臂 J4 超出关节限位 [0.00, 140.00]°。”，看起来像 90° 越界。
- 定位：核对 `logs/openarm/monitor/hardware-9acd4237aac74dfd985c552addec4adf.jsonl`，15 次 J4 拒绝/FAULT 发生前最近的反馈全部是 `-0.0001907377 rad = -0.0109°`，正好一个编码器计数。J4 下限就是 0°，所以真正被 `MotionPlanner._check_pose` 拒绝的是**实测起点**而不是 90° 目标；起点在 0° 两侧一个计数内摆动，所以同样的输入时好时坏，和运动时间/速度无关。POS_VEL 的 `encode_target` 与 POS_FORCE 帧编码对同一读数也会抛 “Position outside mapped joint range”。
- 修复：新增 `openarm_joint_mapping.LIMIT_TOLERANCE = 5e-4 rad`（≈0.029°，约两个编码器步），用于 `_check_pose`、`encode_target`、POS_FORCE 帧编码和反馈限位注记；限位本身（J4 0–140°）不变，超出该容差仍拒绝；拒绝消息追加“本次 ±x.xxx°”，避免再被区间文字误导。
- 离线验证：新增 `test_axis_resting_on_hard_stop_does_not_refuse_the_target`（virtual，起点 `-0.0001907 rad`、目标 90°，预览与执行到保持均通过）；`test_openarm_monitor.py`、`test_openarm_monitor_hands.py`、`test_openarm_position_mode.py`、`test_openarm_execution.py`、`test_openarm_execution_hardware.py` 共 104 项通过（76.24 s）。未连接实机、未使能、未运动，实机复测待现场按授权进行。
