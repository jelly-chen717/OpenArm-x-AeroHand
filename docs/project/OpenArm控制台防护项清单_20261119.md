# OpenArm 控制台防护项清单 · 2026-11-19

> **本清单是根目录 [AGENTS.md](../../AGENTS.md) 第一原则的执行清单。P01～P24 为永久禁止恢复项；K01～K12 为仅允许保留项。**
>
> 场景：用户确认当前 OpenArm 已在工业实验室完成固定，操作人员对运动安全负责。本次按用户要求，删除网页控制台在驱动与控制链路中“因阈值略超就拒绝执行、退出控制或自动失能”的防护，只保留通信、协议、机械限位、停止确认、模式切换和本机访问所必需的检查。
>
> 范围：`monitor-ui/` → `apps/openarm_monitor.py` → `apps/openarm_monitor_motion.py` / `apps/openarm_monitor_modes.py` → `apps/openarm_execution.py` / `apps/openarm_driver.py` → `apps/drive_openarm_from_sim.py` 的 `execute()`。网页模式为 `virtual`，未连接实机，未读写 CAN。

## 2. 保留的检查及理由

这些不是“运动阈值保护”，删除会破坏协议正确性、通信闭环或用户明确要求的停止语义。

| 编号 | 位置 | 保留内容 | 理由 |
| --- | --- | --- | --- |
| K01 | `MotionPlanner._check_pose`、`openarm_position_mode.encode_target`、`openarm_joint_mapping.finite` | 关节位置限位、NaN/非数值拒绝 | 机械限位和坐标有效性；越界目标没有可执行的物理含义。限位比较带 `LIMIT_TOLERANCE`（5e-4 rad ≈0.029°，约两个编码器步）：贴死限位时反馈会读出 0° 以下一个计数（J4 下限正好是 0°），该量化读数不再被当成越界；超出容差仍拒绝，拒绝消息同时给出本次实际角度 |
| K02 | `PcanBus.send`、`decode_feedback`、`encode_mit` | CAN 帧 ID/长度、反馈帧格式、协议字段编码 | 帧格式错误时驱动器不会执行，继续发送无意义 |
| K03 | `PcanBus.open/status`、`query_motor`、`read_parameter` | 通道租约、总线状态、反馈/参数超时 | 通信不可用时无法闭环控制；这是通信故障而非阈值退出 |
| K04 | `Monitor._feedback_view`、`_idle` | 反馈齐全与 `FEEDBACK_AGE=.75 s` 新鲜度 | 不能拿过期反馈规划起点；保留 UI 与预览的必要输入 |
| K05 | `OperatorWatch` / `HEARTBEAT_TIMEOUT=3 s` | 操控页失联超过 3 秒触发停止 | 用户已明确保留的失联停止行为 |
| K06 | `PcanTransport.stop`、`Monitor._hardware_run.require_disabled` | 停止后逐轴失能回读；失败保留 `STOP_UNCONFIRMED` | 用户明确要求“停止未确认”可见；这是停止确认，不是运动阈值 |
| K07 | `ModeRegisters.require_stationary`、`read_modes`、`switch`（`DriveProfile` 继承） | 切模式要求 14 轴静止失能、固件/模式回读、部分失败回退 | 模式寄存器写入的现场协议要求；用户已确认的切换行为 |
| K08 | `ModeRegisters.__init__` / `DriveProfile.__init__` | 完整 C02 盘点、14 轴身份/通道/版本；使用 `DriveProfile` 时另需失能预装与易失写入确认 | 模式寄存器写入的配置完整性准入，不是运行阈值；不约束非 MIT 模式的使能和运动（P20） |
| K09 | `Monitor.start_motion` | 预览归属、请求 ID、revision | 防止重复执行和串页执行；不是跟踪误差保护。预览有效期已删除（P19） |
| K10 | `Journal.record` | 日志写入失败即停止（`journal.error` 锁定运动） | 保留可追溯证据；本次未将其视为“阈值保护”删除 |
| K11 | `create_server` 的校验 | 仅 127.0.0.1、Host/Origin、客户端令牌、JSON 大小/类型 | 本机页面访问控制，与运动阈值无关 |
| K12 | `openarm_trajectory.preflight` | 独立 CLI 的请求版本/时间/起点/速度/加速度预检 | **不在网页路径**：网页由 `MotionPlanner._validate` 直接生成轨迹。保留它是为了不改变 `drive_openarm_from_sim.py` 其他调用方的既有语义 |

## 3. 网页路径的实际效果

- 顶部“全部使能”：不再要求先静止/失能；14 轴按当前角度进入保持，计数来自反馈。可在已有角度（包括 J4≈90°）上直接使能。
- 起始位/0位/回0/钢琴原位：14 轴反馈齐全即可执行，计划自身使能全部 14 轴；不要求先点“全部使能”。试弹在手部不可用时只跳过指法，机械臂照常执行腕位路径。
- 关节/IK 目标：不再因速度/加速度百分比、模型接触、预览后起姿漂移拒绝；预览不再 60 秒失效；目标仍受关节位置限位约束。
- 执行中：跟踪误差、路径点/终点偏差、周期迟到、温度、速度/力矩、相对行程、非指令轴偏移只写日志，不触发 FAULT、不失能、不退出 `HOLDING_TARGET`。
- 非 MIT 位置模式：POS_VEL / VEL / POS_FORCE 与 MIT 一样可直接“全部使能”、预览、执行和保持，不要求现场协议配置。POS_VEL/POS_FORCE 的目标速度或电流比例超出协议量程时按端点饱和并记录提示，不触发 FAULT、不失能；关节位置仍受限位约束。
- 使能与失能特殊帧：四种模式默认发往基础电机 ID，只有目标帧使用模式偏移（POS_VEL `+0x100`、VEL `+0x200`、POS_FORCE `+0x300`），与 OpenArm 官方 CAN 库一致。`--drive-profile` 可逐轴覆盖特殊帧寻址并覆盖 POS_FORCE 电流比例。
- 停止：仍走“停止请求→逐轴失能→回读确认”；回读失败保留“停止未确认”，与用户要求一致。
- 模式切换：仍要求 14 轴静止且失能，并通过协议配置逐轴读回；这是模式写入的现场前提。
