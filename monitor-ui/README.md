# OpenArm 监视控制台

现场联调双击项目根目录的 [01-实机控制台.cmd](../01-实机控制台.cmd)。脚本自动打开 [8092 控制台](http://127.0.0.1:8092/)，连接左臂 `0x51`、右臂 `0x52` 并开始读取反馈。「全部使能」由操作员在网页上点击。已有实机服务时，双击会打开该服务的页面。

双击本目录的 `启动监视控制台.cmd` 可打开 [8091 离线控制台](http://127.0.0.1:8091/)，从 V1 模型初始姿态计算关节与末端坐标。启动脚本使用项目已有的 `openarm/.venv`。

需要指定实机标定或协议文件时，在本目录通过 PowerShell 使用以下命令并附加对应参数。

```powershell
& '.\启动监视控制台.cmd' --mode hardware --left-channel 0x51 --right-channel 0x52
```

实机服务在 [127.0.0.1:8092](http://127.0.0.1:8092/) 监听。连接及重连时读取各轴实际模式，空闲时定期复读。顶部显示 14 轴共同模式，混合时显示“双臂模式不一致”。现场通道为左臂 `0x51`、右臂 `0x52`。

## 实琴琴键与食指原位

现场钢琴为 **C2–C7**（MIDI 36–96），共 **61 键，36 白键、25 黑键**。白键中心距为 **22.5 mm**。实琴白键从低音端 C2 起编为 1–36。既有 TXT 和控制台内部的曲谱白键从 A0 起算，实琴范围内用曲谱白键号减 9 换算。

| 音名 | 实琴白键（C2=1） | 曲谱白键（A0=1） | 用途 |
| --- | ---: | ---: | --- |
| C2 | 1 | 10 | 音域低端 |
| **B3** | **14** | 23 | **左手食指原位** |
| **C4** | **15** | 24 | **右手食指原位**。另有两次独立 C4 调姿记录 |
| B4 | 21 | 30 | 从右食指原位向高音移 6 格 |
| C7 | 36 | 45 | 音域高端 |

双臂原位点位取自截图上方腕部坐标和关节角。左手负责 C2–B3（实琴 1–14），右手负责 C4–C7（15–36）。固定各自 X、Z 和朝向后，左 14 键均有解，右 C4–G6 有 19 组解。右腕到 A6、B6、C7 的所需距离超出模型臂展，表中列出目标坐标，七轴角留空。[双臂原位 Excel](../openarm/skills/paino_skill/双臂钢琴原位_白键点位.xlsx) · [双臂原位 CSV](../openarm/skills/paino_skill/双臂钢琴原位_白键点位.csv)

CSV 中 `physical_white_key` 是实琴白键号，`key` 和双臂表的 `anchor_key` 沿用曲谱白键号。

工作簿首页列出 36 个白键的向外分工和求解状态，分手页列出固定腕姿、实际正解、邻键角差和限位余量。右食指从 F6 到 G6 时 J4 角差为 24.75°，在高音端接近伸直。[标定输入](../configs/openarm_piano_white_keys.json) · [臂展与逐键复核](../docs/project/实琴白键固定腕姿与IK优化_20261123.md)

## 双臂快捷定位

「运动控制」标题行、IK/关节控制左侧按顺序排列四个按钮：

1. **0位**：双臂从当前姿态用 3 秒回到 J1～J6 为 0°、J7 +15°。
2. **回0—起始位**：先回到上述 0 位；再用 3 秒同时执行 J1 +15°、J2 −45°；再用 3 秒执行 J1 −30°（绝对位置）、J2 保持 −45°、J4 +90°；最后用 3 秒执行 J1 保持 −30°、J2 回 0°、J4 +120°，即起始位。
3. **起始位**：跳过前三段，双臂直接从当前姿态用 3 秒回到起始位 **`(-30, 0, 0, 120, 0, 0, 15)°`**（J1 −30°、J4 +120°、J7 +15°）。排练或演奏中只要机械臂仍处于使能保持，即可直接点击，不需要先停止手部或手指排练。
4. **钢琴原位**：加载双臂原位点位表后，可用 3 秒定位至左食指 B3、右食指 C4。

快捷定位只要求 14 轴反馈齐全；计划自身使能全部 14 轴后执行，不要求先点「全部使能」。执行结束保持最终姿态，点「停止并失能」逐轴失能。接口分别为 `POST /api/start/zero`、`POST /api/start/return`、`POST /api/start/pose`、`POST /api/start/piano-origin`，对应日志事件为 `motion.zero_pose`、`motion.start_return`、`motion.start_pose`、`motion.piano_origin`。前三项左右配方镜像，数值相同。钢琴原位使用两侧各自的七轴反馈记录。

## 《槿》和弦试弹与分指预览

### B3/C4 原位逐键定位与双手分指

选择「钢琴原位 · 左 B3 / 右 C4」，选「定位手侧」和「食指白键」，点「预览白键定位」。核对手侧、音名和七轴角后，点击带目标音名的执行按钮。所选臂用 3 秒定位，另一臂已在保持的轴沿用原目标。各键目标保持该侧原位的 X、Z 和腕部朝向，音高每升一个白键，Y 减少 22.5 mm。运动沿用关节插补，途中的 X、Z 可随姿态变化。旧服务加载新版前，须先在现场结束保持、关闭旧进程，再打开根目录的「01-实机控制台.cmd」。

选「琴谱」及「首和弦」「前奏前四小节」或「全曲」，点「预览双手指法」。预览可在失能时打开。两份谱共用 B3/C4 点位表，左手负责 C2–B3，右手负责 C4–C7。纯和弦版 347 组起音、1,300 音的腕位均有解。60 BPM 完整钢琴版按同一时刻按住的音高查找腕位，标出当前指距需要调整的组。两侧都有点位时，页面显示两腕控制点距离，首组另显示基座坐标系的 XYZ 和 J1–J7。[实琴分手谱](../docs/project/仿真与实机联通_两日实施计划.md#piano-adjacent-origin) · [完整钢琴版](../docs/project/仿真与实机联通_两日实施计划.md#piano-jin-full-score)

首拍由左中指弹 F3、左食指弹 A3、右食指弹 C4、右无名指弹 E4。右腕在修正后的 C4 原位，两腕控制点相距 132.90 mm。实际指尖落键与两手净空待现场核对。[分指复核](../docs/project/仿真与实机联通_两日实施计划.md#piano-adjacent-origin)

### 两组右手 C4 腕姿

同一面板也可选择右 C4 的 17:35 或 17:45 腕姿，使用两次 C4 现场标定的关节角。两组 C4 腕姿可选实琴白键 12–29（曲谱 21–38），默认 C4。首次定位沿途先到粗定位 `(8, 0, 0, 90, 0, 0, 2)°`，再到 C4，改选其他键时接着移到目标。同组定位保持期间可直接选相邻键观察落点。[两组 C4 点位 Excel](../openarm/skills/paino_skill/右手食指_实机白键点位与关节角_20261122.xlsx)

在「Aero 手部控制」连接右手，使用对应实机或模拟会话保存的按下、抬起角度。选择 C4 腕姿和「首和弦」，点「预览右手试弹」→「开始右手试弹」。从同组 C4 定位接续时，先用 0.25 秒抬指准备。现有试弹的首和弦为 C4、E4（实琴白键 15、17，曲谱白键 24、26）。未连接右手、会话变更或未记录按抬位时，机械臂仍执行腕位路径，指法跳过并在日志记 `hand.score.skipped`。「停止并失能」沿用联合停止流程。

「前奏前四小节」包含 16 个右手音，「全曲」包含 694 个右手音。倍率范围为 0.35× 至 1×。程序从 C4 点位 CSV 读取七轴角度，按实琴分手版纯和弦谱换腕、按指和抬指。全曲食指腕位为 C4、D4、E4、A4（实琴白键 15、16、17、20，曲谱白键 24、25、26、29）。左臂已在保持的轴沿用原目标。其他手指的实际落点待上琴核对。[C4 点位 CSV](../openarm/skills/paino_skill/右手食指_实机白键点位与关节角_20261122.csv) · [纯和弦谱](../openarm/skills/paino_skill/music_data/槿（实琴分手·纯和弦）.txt)

## 《槿》双臂空弹

在「运动控制 → 《槿》双臂空弹」选择琴谱，点击「琴谱起位」。程序用 4 秒移到该谱的双臂起位并保持。现场确认腕位后，选择「开头 16 秒」或「整份琴谱」，点「预览空弹」，再点「开始空弹」。从同一琴谱的起位保持接续时，谱面从 0 秒开始，开头的休止照常计时。

倍率可选 0.35×–1×，步长 0.01×，默认 0.35×。原谱 1× 为 60 BPM。运行时面板显示谱面时间和当前白键。空弹只驱动双臂，手指事件随谱面和目标写入 JSONL。

| 琴谱 | 左手起位（曲谱白键） | 右手起位（曲谱白键） | 起拍（曲谱白键） |
| --- | --- | --- | --- |
| 《槿》主旋律 | 小指 19、食指 23 | 食指 24 | 左手白键 22 |
| 《槿》纯和弦 | 小指 18、食指 22 | 食指 24 | 左中指 20、左食指 22、右食指 24、右无名指 26 |
| 《槿》副歌纯旋律 | 小指 19、食指 23 | 食指 30 | 右中指 31 |

三份谱各自保留原有音高和按抬节拍。纯和弦的 347 组起音共 1,300 音，双侧各自按空弹指距分配同拍按键，换位可以利用上一组起音后的空中时间。1× 含 4 秒起位时，主旋律 236 秒、纯和弦 312 秒、副歌纯旋律 36 秒。

预览会显示坐标来源。默认「CSV 仿真坐标」用于比对仿真腕位。原始 CSV 起位与此前记录的右臂 24 键现场定位属于两套坐标。和弦起位在 V1 标准夹爪和现有 Aero 休止姿态模型中均出现双手接触。实机需要核对腕端、支架与线缆净空。现场可以启动时加 `--piano-calibration <测量文件.json>`，提供两侧各自实测的腕位和琴键方向。

- 空弹接口的 `anchor_q_rad.left` 取左小指 E3／食指 B3 的参考姿态，`anchor_q_rad.right` 取右食指 C4 的参考姿态。数值为 J1～J7 模型角，单位 rad。这组接口参考位置沿用曲谱的 19／23 和 24，快捷「钢琴原位」使用上表的 B3 与 C4。
- `key_step_m` 填从低音向相邻高音白键的三维基座位移，单位 m。实琴点位表采用 `[0, -0.0225, 0]`，仿真 CSV 采用 `[0, -0.0235, 0]`。
- 首次实机从「琴谱起位」验收，随后走短句和整份琴谱。8092 启动新版服务后加载三份谱。离线虚拟服务使用 8091。

## Aero 手部手动操作

在「运动控制」展开「Aero 手部控制」，面板默认显示右手。8091 使用软件模拟，8092 默认右手选择「实机串口」并预填 COM7，左手默认模拟。点「连接并读取」获取七路反馈与初始位置。每只手可分别设置连接方式，实机串口由一个程序独占。

选择食指、中指、无名指或小指，输入目标角度并点「发送角度」。观察指尖和反馈，在需要的位置点击「记录当前为抬起位」或「记录当前为按下位」。之后可直接点「按下」或「抬起」。每次只更新所选指，其余通道沿用上次目标，首次沿用连接时读到的位置。控制台优先读取 configs 下按手侧和模式保存的 aero_monitor 标定文件，首次采用 Aero 双手工具里的对应初值。

「停止并断开」关闭所选手的串口，舵机可能继续保持最后目标。机械臂执行时，页底「停止并失能」同时停止臂任务并断开已连接的双手。手部按钮每次只发一个目标。操作和错误记录在该次控制台会话的 JSONL 日志中。

### 在 8092 排练《槿》

1. 在「运动控制 → Aero 手部控制」连接右手实机 COM7，然后切到左手，保留「模拟」并点「连接并读取」。在已安装的手腕姿态下核对右手各指的按下位和抬起位。若现场另接了左手，选择它实际使用的串口并独立标定。
2. 在同一面板的「《槿》实琴分手版纯和弦」下点「开始手指排练」。程序读取谱内四指 TXT 指令。全曲 312 秒，前 4 秒保留定位时间。第 4 秒左右手各自的食指、无名指同时按下，第 5.72 秒抬起。实际音高取决于手腕所在键位，实琴指法见谱内「实琴」行。
3. 点「停止排练」结束双方的后续谱面指令，向此次仍按住的手指发送抬起目标，双手连接可继续点动。保持发起排练的页面打开。停止、通信故障或操控页心跳丢失的结果显示在排练按钮下方，实际离键需观察指尖。

## 顶部的电机控制

双臂静止失能后，从顶部“电机模式”选择目标。实机确认框列出左右 J1～J7 原模式、目标和回退方式；取消会恢复原选项。确认后由 CAN 工作线程复核原值，逐轴切换再独立读回，发生部分失败时恢复已尝试轴的原值。切换只改运行模式，不保存 Flash。运动面板的“关节控制 / IK 控制”选择目标的输入方式。

| 电机模式 | 位置目标如何执行 |
| --- | --- |
| MIT · 阻抗 | 发送位置、速度和关节增益。到位后持续发送目标角和零目标速度。 |
| POS_VEL · 位置速度 | 发送轨迹位置与正的速度上限，由驱动器闭合位置环。 |
| VEL · 速度 | 控制台根据轨迹速度和角度误差计算限幅速度。到位后外环继续纠正偏差。 |
| POS_FORCE · 力位混合 | 发送位置、速度上限和电流标幺上限。未加载现场协议配置时使用 10%，加载后使用配置值。 |

点击“全部使能”后，左右 J1～J7 以各自当前角度进入保持，不要求先回到静止或失能姿态。顶部计数来自关节反馈，14/14 表示两臂都已确认使能。“全部使能”也可跳过，直接执行预览会使能有位移的轴。离线使用理想空载模型，可检查控制帧和操作流程，带载精度与电流响应需要实测。

## 实验室模式：已删除的非必要防护

> 本节是工作区**第一原则**的执行说明，原则全文见根目录 [AGENTS.md](../AGENTS.md)。下列已删除项**永久禁止重新写回**；任何新增的阻断执行检查都必须先取得用户当次明确授权。

当前配置面向已固定、由操作人员负责的工业实验室场景。以下条件只记录，不再拒绝执行、触发 FAULT、退出控制或自动失能：

- 跟踪误差、路径点/终点偏差、控制周期迟到、运行中请求过期；
- 反馈速度、力矩、温度、相对行程、反馈年龄、非指令轴偏移；
- 预览所需速度/加速度超过速度百分比或 1 rad/s²；
- 预览后实测起姿漂移；模型接触扫描；
- 使能前的“必须静止且失能”要求；
- 起始位/0位/回0/钢琴原位前的“14 轴已使能”前置（计划自行使能全部 14 轴）；
- 试弹前的手部连接、会话与按抬位前置（手部不可用时只跳过指法）；
- 运动起点模式/固件读回不一致（只记录 `mode_readback` 提示）；
- 接续执行时反馈不完整（改用缓存反馈与计划起点继续，记 `motion.continuation_adopted`）。

MIT 位置/速度/增益/力矩超出协议量程时按端点饱和编码；POS_VEL / POS_FORCE 的目标速度或电流比例超出协议上限时按上限发送并记录提示，均不再抛错。完整清单、逐项位置和保留项见 [OpenArm 控制台防护项清单](../docs/project/OpenArm控制台防护项清单_20261119.md)。

仍然保留：关节位置限位、NaN/映射/帧格式校验、CAN 通信超时、停止后的逐轴失能回读（失败显示“停止未确认”）、模式切换的静止失能前提与逐轴模式回读、本机 Host/Origin/客户端令牌校验、操控页 3 秒心跳停止。

## 操作

1. 选择关节控制或 IK，以及左臂、右臂或双臂。关节目标使用标定零点和当前逻辑方向。点「填入当前位置」可按所选各臂把当前关节角填入 7 轴目标，再作调整；填写希望调整的关节，留空跳过该轴。IK 使用基座系毫米坐标和当前手腕朝向，可把当前坐标填入表单再作调整。预览从多个初始关节姿态求解，在符合关节限位和位姿精度要求的解中选择离当前关节姿态最近的一组。搜索结束时若未找到解，页面显示“未找到收敛解”。离线模式支持 Aero 固定手指模型的指尖，实机 IK 使用 J7 手腕控制点。
2. 设定运动时间和额定速度百分比，预览目标。网页按各关节的标定角度范围规划，执行器根据本次起点和目标计算各轴行程。速度百分比是规划基准；若目标时间要求更高速度或加速度，按本次所需值放行并在预览中显示峰值，不再拒绝。实机路径不再做模型接触扫描。
3. 对照预览的角度和指令轴，单击执行。预览不再设 60 秒有效期；执行前仍以当前反馈重建轨迹，预览后的起姿漂移会被采纳。终点误差、跟踪误差、路径点偏差和周期迟到只记录为提示，不再中断执行或失能；执行结束进入“已到位 · 使能保持中”。同一页面可继续预览和执行已使能轴的新目标，其余已使能轴维持原目标。需要增加参与轴时，先停止，再选择全部使能。
4. 点击“停止并失能”，等待使能计数回到 0/14 后可以切换模式。操控页失联超过 3 秒、运行故障或服务正常关闭都会触发停止。实机停止会核对两臂失能回读，回读失败显示“停止未确认”。

## 实机多模式的接入条件

实机启动默认使用 `configs/openarm_position_mode.json` 的 `monitor_inventory` 指向本机 14 轴 C02 盘点，也可用 `--mode-inventory <inventory.json>` 显式指定。切换时核对固件与通道。缺少盘点时仍显示实际模式，模式写入按钮不可用。加载盘点后即可在失能状态切换四种寄存器模式。

四种模式都可直接“全部使能”、预览、执行和保持，不要求现场协议配置。目标帧按模式偏移发送（POS_VEL 为 `基础ID + 0x100`，VEL `+0x200`，POS_FORCE `+0x300`）；使能/失能的 `0xFF×7 + 0xFC/0xFD` 特殊帧默认发往基础电机 ID，与 OpenArm 官方 CAN 库 `create_enable_command` / `create_disable_command` 的实现一致。[现场盘点](../logs/openarm/mode_switch/20261119_171446/inventory.json)

现场若核实到某轴固件要求特殊帧使用模式偏移，可在启动时附加 `--drive-profile <现场协议配置.json>` 覆盖。未提供该文件时按基础 ID 与 10% 电流比例执行。配置使用 UTF-8 JSON，包含以下字段。

| 字段 | 内容 |
| --- | --- |
| `inventory` | 完整 C02 备份 JSON 的路径，可相对协议配置文件。程序检查映射、两臂通道、14 轴身份、寄存器和失能记录。 |
| `special_frame_address` | 对象含 `left`、`right` 两个数组，各按 J1～J7 填写经核实的 `base` 或 `mode`，分别指基础 ID 或模式偏移 ID。 |
| `disabled_preload_verified`、`volatile_mode_write_verified` | 两项均为布尔值。现场确认 14 轴能够在失能时预装当前目标、模式寄存器写入可易失生效后填 true。 |
| `pos_force_current_fraction` | 已核实适用于双臂的最大相电流比例，范围 0.0001～1。 |

加载盘点启动后，先在失能状态选择模式。服务核对各轴硬件、软件和子版本，逐轴写入需要变化的 CTRL_MODE，独立读取全部 14 轴后开放使能。部分写入失败时按原值回退已尝试的轴，页面保留故障并锁定执行。网页切换流程不发 Flash 保存命令。再次连接后应重新确认模式。运动起点仍会读取各轴固件与模式：与控制台选择不一致或读回失败只记 `mode_readback` 提示，不拒绝该次运动。

## 反馈与日志

- 关节表可切换角度、速度、力矩、温度与电机状态。反馈过期时对应关节显示空值。实机手腕坐标由 CAN 关节回读经 V1 正运动学换算。
- 重要反馈区显示进度、到位、取消、故障和跟踪偏差。运动中的偏差逐周期记录，轨迹结束时记录终点误差并进入保持；偏差不再阻止到位。执行日志可按等级筛选，按事件、参数或指令编号搜索。
- “导出 JSONL”下载当前服务会话的完整日志，包含控制参数、逐周期目标、观测、偏差和停止回读。原始文件保存在 `logs/openarm/monitor`。每条记录带有 `mode`，同一条指令用 `request_id` 关联。

WEB04 的四种模式已完成离线浏览器验证。实机协议分支通过替身 CAN 测试。WEB03 历史实机记录覆盖反馈和失能，WEB04 的实物模式切换、14 轴使能和带载保持待验收。WEB05 已删除上述非必要运动阈值防护，并重新完成离线测试与浏览器操作；实机行为仍按同一现场边界待验收。WEB08 起 POS_VEL 等非 MIT 模式不再要求现场协议配置即可使能和运动，替身 CAN 已验证，实机使能与带载运动仍待现场验收。
