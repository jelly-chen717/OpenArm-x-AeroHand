# OpenArm 监视控制台

现场联调双击项目根目录的 [01-实机控制台.cmd](../01-实机控制台.cmd)。脚本自动打开 [8092 控制台](http://127.0.0.1:8092/)，连接左臂 `0x51`、右臂 `0x52` 并开始读取反馈。「全部使能」由操作员在网页上点击。已有实机服务时，双击会打开该服务的页面。

更新后要重启 8092 时，先在网页停止操作并确认双臂失能，再双击根目录的 [停止旧控制台-8092.cmd](../停止旧控制台-8092.cmd)。看到端口已释放后，双击实机启动脚本加载新版。

双击本目录的 `启动监视控制台.cmd` 可打开 [8091 离线控制台](http://127.0.0.1:8091/)，从 V1 模型初始姿态计算关节与末端坐标。启动脚本使用项目已有的 `openarm/.venv`。

需要指定实机标定或协议文件时，在本目录通过 PowerShell 使用以下命令并附加对应参数。

```powershell
& '.\启动监视控制台.cmd' --mode hardware --left-channel 0x51 --right-channel 0x52
```

实机服务在 [127.0.0.1:8092](http://127.0.0.1:8092/) 监听。连接及重连时读取各轴实际模式，空闲时定期复读。顶部显示 14 轴共同模式，混合时显示“双臂模式不一致”。现场通道为左臂 `0x51`、右臂 `0x52`。

## 实琴琴键与食指原位

现场钢琴为 **C2–C7**（MIDI 36–96），共 **61 键，36 白键、25 黑键**。白键中心距为 **22.5 mm**。实琴白键从低音端 C2 起编为 1–36。既有 TXT 和控制台内部的曲谱白键从 A0 起算，实琴范围内用曲谱白键号减 9 换算。

| 音名 | 实琴白键（C2=1） | 曲谱白键（A0=1） | 用途 |
| --- | ---: | ---: | --- |
| C2 | 1 | 10 | 音域低端 |
| **A3** | **13** | 22 | **左手食指原位** |
| B3 | 14 | 23 | 左食指从 A3 向中央移动一格 |
| **C4** | **15** | 24 | **右手食指原位** |
| C7 | 36 | 45 | 音域高端 |

基座系原位 XYZ 为左 A3 **(250.19, 56.1, −170.00) mm**、右 C4 **(250.25, −55.0, −170.00) mm**。以两侧原实测关节角的腕部朝向为参考，求出新坐标的七轴目标。左手负责 C2–B3（实琴 1–14），右手负责 C4–C7（15–36）。各手按食指、中指、无名指、小指排列，左手原位为 **A3、G3、F3、E3**，右手原位为 **C4、D4、E4、F4**。[标定输入](../configs/openarm_piano_white_keys.json)

CSV 中 `physical_white_key` 是实琴白键号，`key` 和双臂表的 `anchor_key` 沿用曲谱白键号。

固定各手原位的 X、Z 和朝向后，左 C2–B3 有 14 组角，右 C4–G6 有 19 组角。右 A6、B6、C7 的食指目标超出模型臂展，表中保留目标坐标和状态。食指对 G6 时，右中指、无名指、小指可分别覆盖这三个音。工作簿同时列出正解误差、邻键角差和限位余量。[双臂原位 Excel](../openarm/skills/paino_skill/双臂钢琴原位_白键点位.xlsx) · [双臂原位 CSV](../openarm/skills/paino_skill/双臂钢琴原位_白键点位.csv)

[现行与历史末端位姿版本索引](../docs/archive/piano-calibration/README.md)

## 快速复标计划

一次复标维护一份标定 JSON，生成一份控制台 CSV。预览、八指估算、试弹和整曲都从这套数据生成。以下流程适用于左食指 A3、右食指 C4，分手为左 C2–B3、右 C4–C7，且每只手在其音域内使用固定 X、Z 和腕姿的琴位。[标定配置](../configs/openarm_piano_white_keys.json) · [点表生成器](../apps/build_openarm_piano_points.py)

| 场景 | 改哪些字段 | Y 怎么处理 |
| --- | --- | --- |
| 临时试一个前后或上下位置 | 在控制台「IK → 手腕」填目标 XYZ，点「求解与预检」 | Y 填该音当前点表的 Y。原位调试时用对应手的原位 Y |
| 正式更新 X/Z | 修改动过一侧 `wrist_xyz_mm` 的第 1、3 项。沿用腕姿时用 `reference_joints_deg` 保存参考角，重算原位 | 原位 Y 沿用当前值。现行左 A3 为 56.1 mm，右 C4 为 −55.0 mm |
| 正式更新 XYZ | 修改动过一侧的整组 `wrist_xyz_mm` 和新的 `joints_deg` | 每手用新原位 Y。使用同一架琴和同一朝向时，白键距沿用 22.5 mm，升一格沿 −Y |

现行生成公式为 `Y(k) = Y原位 − 22.5 × (k − k原位)`，其中 `k` 从实琴 C2=1 起数。以左 A3 的 Y 为 56.1 mm 为例，只改 X/Z 时，B3 仍为 33.6 mm。若左 A3 的新 Y 为 60.0 mm，B3 改为 37.5 mm，仍相差 22.5 mm。

### 取原位数据

1. 沿用原位腕姿且已有目标 X/Z 时，更新配置并用 `reference_joints_deg` 保存旧实测角，运行生成器即可得到新原位角。需要在控制台预览时，在「运动控制」选 IK 和「手腕」，填写 XYZ 与接手记录里的 Roll、Pitch、Yaw，再点「求解与预检」。[现行原位腕姿](../docs/project/仿真与实机联通_两日实施计划.md#piano-a3-c4-xz)
2. 现场对键到位后，在同一姿态读取基座系 XYZ（mm）和「本次关节反馈」的 J1–J7（度）。左食指对 A3，右食指对 C4。只调 X/Z 时，预览中显式填入配置里的原位 Y，对键后用实际读数复核该轴。
3. 如果已有新原位的七轴实测角，将该侧参考角字段换成 `joints_deg`。同时写入目标 XYZ，仅调整 X/Z 时沿用配置中的 Y。在 `source` 记录日期和来源。生成器直接采用 `joints_deg`；使用 `reference_joints_deg` 时先计算固定腕姿，再对原位和逐键目标求逆解。

### 生成、检查和发布

| 步骤 | 操作 | 完成标志 |
| --- | --- | --- |
| 1. 留存旧标定 | 在改配置前保存当前 JSON 和运行 CSV | 两文件放在同一个复标目录，便于成对恢复 |
| 2. 出候选点表 | 改配置后运行生成器，先写候选 CSV | 36 行，左 14 行、右 22 行。复核两个原位的 `fk_dx_mm`、`fk_dy_mm`、`fk_dz_mm` |
| 3. 抽查腕位 | 看左 A3→B3、右 C4→D4、左 C2 和右高音端。对照上版的可达状态 | 左右各向高音一格均为 Y 减 22.5 mm。记录新增无解键和可替代手指 |
| 4. 快速回放 | 结束本轮操作并关闭旧 8092 后，发布 CSV，离线回放全曲库 | 核对新增错音、漏音、跳过音和等待点。现行 196 个 C2 以下的跳过音可作为对照 |
| 5. 重启与抽验 | 重启 8092，核对左 A3、右 C4 的原位角和八指音名，另抽查左 B3。选《槿》纯和弦看首拍，选《小苹果》检查入位等待 | 控制台显示新原位角，各手首腕位正确，入位后等待 2 秒再按该曲倍率起奏 |

本机用现行标定实测，生成 36 键用时 30.6 秒，控制器回放 58 首用时 8.8 秒。对键、读数和现场抽验另计。以下命令在同一 PowerShell 窗口按顺序运行。先保存当前文件。

```powershell
Set-Location -LiteralPath 'D:\桌面\open CyMon\弹钢琴'
$pianoPython = '.\openarm\.venv\Scripts\python.exe'
$pianoConfig = '.\configs\openarm_piano_white_keys.json'
$pianoPoints = '.\openarm\skills\paino_skill\双臂钢琴原位_白键点位.csv'
$pianoRun = Join-Path '.\logs\openarm\sync' ('piano-recal-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $pianoRun | Out-Null
Copy-Item -LiteralPath $pianoConfig -Destination (Join-Path $pianoRun 'previous-config.json')
Copy-Item -LiteralPath $pianoPoints -Destination (Join-Path $pianoRun 'previous-points.csv')
```

填入新反馈后，生成候选点表并查看原位和边缘键。

```powershell
$pianoCandidate = Join-Path $pianoRun 'candidate.csv'
& $pianoPython -B .\apps\build_openarm_piano_points.py $pianoCandidate
if ($LASTEXITCODE -ne 0) { throw '点表生成失败' }
$pianoRows = Import-Csv -LiteralPath $pianoCandidate
$pianoRows | Group-Object arm, status | Select-Object Name, Count
$pianoRows | Where-Object note -in @('C2','A3','B3','C4','D4','G6','A6','B6','C7') |
  Format-Table arm, note, physical_white_key, key, x_mm, y_mm, z_mm, status, fk_dx_mm, fk_dy_mm, fk_dz_mm
```

候选表核对后，发布并跑控制器回放。

```powershell
Copy-Item -LiteralPath $pianoCandidate -Destination $pianoPoints
& $pianoPython -B .\apps\verify_openarm_piano_performance.py --controller-only --output (Join-Path $pianoRun 'replay.json')
if ($LASTEXITCODE -ne 0) { throw '回放未通过，先检查终端和回放结果' }
```

回放失败或出现待排查的新差异时，先查本轮结果。需恢复上版时，将同目录的 `previous-config.json` 和 `previous-points.csv` 分别复制回 `$pianoConfig` 和 `$pianoPoints`，再启动控制台。实机启动入口在 8092 有旧进程时会复用它，重启时先关闭原服务。[实机控制台启动入口](../01-实机控制台.cmd)

### 何时扩大工作量

- 曲谱 TXT 在选曲时按原音高和按抬时序自动重编腕位与指法。发布当前点表时，用同次 CSV 同步工作簿，更新在用曲谱中的原位注释，并链接本轮回放结果与接手记录。
- 首拍换了对键或用指、电子回放出现新增跳过，或高音可达状态改变时，用相关曲目补跑 MuJoCo 触键。首和弦可用 `--score jin-chords`，快速换腕可用 `--score little-apple`，高音可用 `--score '不再犹豫'`。沿用核验脚本并去掉 `--controller-only`。双掌净空、实际键程和发声由现场抽验。
- 仅当实际白键距改变时，调整 `white_key_pitch_mm` 并同步核验脚本中的 22.5 mm 投影参数。琴面转角、倾斜或个别键需要独立 X/Z 时，按实测的相邻键 XYZ 位移扩展生成模型。运行固定数值的回归用例时，同步原位角、B3 坐标和高音可达状态等标定快照。[核验脚本](../apps/verify_openarm_piano_performance.py) · [点表回归](../apps/test_openarm_piano_points.py) · [控制台回归](../apps/test_openarm_monitor.py)

## 双臂快捷定位

「运动控制」标题行、IK/关节控制左侧按顺序排列四个按钮：

1. **0位**：双臂从当前姿态用 3 秒回到 J1～J6 为 0°、J7 +15°。
2. **回0—起始位**：先回到上述 0 位；再用 3 秒同时执行 J1 +15°、J2 −45°；再用 3 秒执行 J1 −30°（绝对位置）、J2 保持 −45°、J4 +90°；最后用 3 秒执行 J1 保持 −30°、J2 回 0°、J4 +120°，即起始位。
3. **起始位**：跳过前三段，双臂直接从当前姿态用 3 秒回到起始位 **`(-30, 0, 0, 120, 0, 0, 15)°`**（J1 −30°、J4 +120°、J7 +15°）。排练或演奏中只要机械臂仍处于使能保持，即可直接点击，不需要先停止手部或手指排练。
4. **钢琴原位**：用 3 秒定位至左食指 A3、右食指 C4，目标为点表中的两组原位关节角。

快捷定位只要求 14 轴反馈齐全；计划自身使能全部 14 轴后执行，不要求先点「全部使能」。执行结束保持最终姿态，点「停止并失能」逐轴失能。接口分别为 `POST /api/start/zero`、`POST /api/start/return`、`POST /api/start/pose`、`POST /api/start/piano-origin`，对应日志事件为 `motion.zero_pose`、`motion.start_return`、`motion.start_pose`、`motion.piano_origin`。前三项左右配方镜像，数值相同。

## 钢琴定位与试弹

### 整曲弹奏

「整曲弹奏」显示双臂 14 轴反馈和两手连接类型。选谱后点击 **「弹奏」**，以同一条请求提交双臂轨迹和指法。在 Aero 面板可分别连接两手并核对参与手指的按下位和抬起位。

「弹奏」右侧显示所选谱面需要的手部状态。未连接或反馈异常时显示红字。实机控制台连接模拟手、按下位或抬起位需要核对时显示黄字。两手就绪时显示绿色连接状态。手部会话或所需标定不可用时，腕位轨迹继续执行，页面显示 `hand.score.skipped` 的原因。

曲谱先抬指，再调用 A3／C4 钢琴原位，从原位移至各手首个演奏腕位并保持 **2 秒**。《槿》主旋律与《小苹果》默认 **0.8×**，《槿》纯和弦为 **1×**。

曲中换位侧等四指读回距各自标定抬起位不超过 2° 后移动。下一组落键等待两个臂反馈周期均满足腕位 XYZ 距离不超过 5 mm、J7 距目标不超过 1.5°。等待时双臂继续保持当前轨迹目标，两手共用时钟。页面显示等待抬指、腕位偏差和累计反馈等待时间。

《槿》主旋律、纯和弦和《小苹果》的换位使用梯形速度。J7 指令相对同一轨迹抬高 2°，从换位时间的 60% 开始回落，在 90% 恢复。《小苹果》相邻一白键的换位使用单独的速度上限。模型侧 J1、J2、J5–J7 为 4.4 rad/s，J3、J4 按额定速度约 3.77 rad/s。

定位、等待起奏和演奏期间，点击 **「退出演奏」** 即可结束当前曲谱。双臂在实测关节位置保持使能，参与演奏的手指回到标定抬起位，手部连接保留。退出后可直接选曲重播或执行其他位置目标。需要结束使能保持时，点「停止并失能」。

控制台启动时枚举曲库的 58 首四指谱。选曲时读取原谱音高、分手和按抬时序，用同一份实琴 CSV 编排。《槿》主旋律、副歌、纯和弦、完整钢琴版和《小苹果》共 3,543 音已逐音核对。《小苹果》首腕位左 A2／右 G4，259 音，当前 0.8× 正式段 79.880371 秒。超出实琴范围的原音标记为跳过，页面显示对应音数。[本轮逐谱核验](../logs/openarm/sync/piano_a3_c4_xz_20261125.json)

### 逐键定位与双手指法

在「钢琴定位与试弹」选「定位手侧」和「食指白键」，点击「预览白键定位」。核对音名和七轴角后执行。所选臂用 3 秒定位，另一臂已保持的轴沿用原目标。每手使用原位的 X、Z 和腕部朝向，白键每升一格，Y 减少 22.5 mm。左 A3→B3 为向中央移动，B3 的目标坐标为 (250.19, 33.6, −170.00) mm。腕位之间沿用关节插值。

选曲后可按「首拍」「前奏（16 秒）」或「全曲」预览双手指法。每组显示原音、食指所对的白键和实际用指。两手同时有目标时显示两腕控制点距离。各手首次出现腕位时另显示基座系 XYZ 和 J1–J7。预览、试弹和正式播放共用当前实琴点表。

《槿》纯和弦与完整钢琴版首拍均为左 **无名指 F3、食指 A3**，右 **食指 C4、无名指 E4**。两手位于标定原位，两腕控制点相距约 111.10 mm。[首拍与换腕核验](../docs/project/仿真与实机联通_两日实施计划.md#piano-a3-c4-xz)

### 联动试弹

1. 在 Aero 面板连接参与的手，核对按下位和抬起位。
2. 选择琴谱、范围、试弹手侧和 0.35×–1× 倍率，点「预览试弹」后执行。支持双手或仅右手。从已保持的首腕位接续时，抬指后即可试弹。
3. 同一手的换腕安排在该手抬指之后。会话缺失时，页面显示指法未启动原因，机械臂继续执行腕位。跳过音会在预览和状态中显示，其他音符照常编排。

11 月 22 日两组右 C4 调姿是独立的历史测量。[历史工作簿](../docs/archive/piano-calibration/2026-11-22_C4/右手食指_实机白键点位与关节角_20261122.xlsx)

## Aero 手部手动操作

在「运动控制」展开「Aero 手部控制」，面板默认显示右手。8091 使用软件模拟。8092 读取 Aero 上位机保存的连接方式和串口，现行配置为左手 COM10、右手 COM7。逐手点「连接并读取」获取七路反馈与初始位置。每只手可分别设置连接方式，实机串口由一个程序独占。

选择食指、中指、无名指或小指，输入目标角度并点「发送角度」。观察指尖和反馈，在需要的位置点击「记录当前为抬起位」或「记录当前为按下位」。之后可直接点「按下」或「抬起」。每次只更新所选指，其余通道沿用上次目标，首次沿用连接时读到的位置。控制台优先读取 configs 下按手侧和模式保存的 aero_monitor 标定文件，首次采用 Aero 双手工具里的对应初值。

「停止并断开」关闭所选手的串口，舵机可能继续保持最后目标。页底「停止并失能」停止臂任务并失能，结束正在进行的指法播放并抬起播放中仍按住的手指。双手保留原连接，播放结束后可直接点动。手部按钮每次只发一个目标。操作和错误记录在该次控制台会话的 JSONL 日志中。

### 在 8092 排练《槿》

1. 在「运动控制 → Aero 手部控制」分别连接右手 COM7、左手 COM10。在已安装的手腕姿态下核对两手各指的按下位和抬起位。单手排练时，可将另一侧切为模拟并连接。
2. 在同一面板的「《槿》实琴分手版纯和弦」下点「开始手指排练」。程序读取谱内四指 TXT 指令。全曲 312 秒，前 4 秒保留定位时间。第 4 秒左右手各自的食指、无名指同时按下，第 5.72 秒抬起。实际音高取决于手腕所在键位，实琴指法见谱内「实琴」行。
3. 点「停止排练」结束双方的后续谱面指令，向此次仍按住的手指发送抬起目标，双手连接可继续点动。保持发起排练的页面打开。停止、通信故障或操控页心跳丢失的结果显示在排练按钮下方，实际离键需观察指尖。

## 顶部的电机控制

双臂静止失能后，从顶部“电机模式”选择目标。实机确认框列出左右 J1～J7 原模式、目标和回退方式；取消会恢复原选项。确认后由 CAN 工作线程复核原值，逐轴切换再独立读回，发生部分失败时恢复已尝试轴的原值。切换只改运行模式，不保存 Flash。运动面板的“关节控制 / IK 控制”选择目标的输入方式。

| 电机模式 | 位置目标如何执行 |
| --- | --- |
| MIT · 阻抗 | 发送位置、速度和关节增益。到位后持续发送目标角和零目标速度。 |
| POS_VEL · 位置速度 | 发送轨迹位置与正的速度上限，由驱动器闭合位置环。 |
| VEL · 速度 | 控制台根据轨迹速度和角度误差计算限幅速度。到位后外环继续纠正偏差。 |
| POS_FORCE · 力位混合 | 发送位置、速度上限和电流标幺上限。未加载现场协议配置时使用 10%，加载后使用配置值。 |

点击“全部使能”后，左右 J1～J7 以各自当前角度进入保持，不要求先回到静止或失能姿态。顶部计数来自关节反馈，14/14 表示两臂都已确认使能。“全部使能”也可跳过，直接执行预览会使能有位移的轴。离线使用理想空载模型，可检查控制帧和操作流程，带载精度与电流响应需要实测。

## 实验室模式：已删除的非必要防护

> 本节是工作区**第一原则**的执行说明，原则全文见根目录 [AGENTS.md](../AGENTS.md)。下列已删除项**永久禁止重新写回**；任何新增的阻断执行检查都必须先取得用户当次明确授权。

当前配置面向已固定、由操作人员负责的工业实验室场景。以下条件只记录，不再拒绝执行、触发 FAULT、退出控制或自动失能：

- 跟踪误差、路径点/终点偏差、控制周期迟到、运行中请求过期；
- 反馈速度、力矩、温度、相对行程、反馈年龄、非指令轴偏移；
- 预览所需速度/加速度超过速度百分比或 1 rad/s²；
- 预览后实测起姿漂移；模型接触扫描；
- 使能前的“必须静止且失能”要求；
- 起始位/0位/回0/钢琴原位前的“14 轴已使能”前置（计划自行使能全部 14 轴）；
- 试弹前的手部连接、会话与按抬位前置（手部不可用时只跳过指法）；
- 谱面缺分指/腕位、换腕与按住重叠、演奏编排无共同腕位（只跳过该组指法或音组，机械臂继续）；
- 运动起点模式/固件读回不一致（只记录 `mode_readback` 提示）；
- 接续执行时反馈不完整（改用缓存反馈与计划起点继续，记 `motion.continuation_adopted`）。

MIT 位置/速度/增益/力矩超出协议量程时按端点饱和编码；POS_VEL / POS_FORCE 的目标速度或电流比例超出协议上限时按上限发送并记录提示，均不再抛错。完整清单、逐项位置和保留项见 [OpenArm 防护删除总纲](../docs/project/OpenArm防护删除_总纲_20261125.md) 第 2 章。

仍然保留：关节位置限位、NaN/映射/帧格式校验、CAN 通信超时、停止后的逐轴失能回读（失败显示“停止未确认”）、模式切换的静止失能前提与逐轴模式回读、本机 Host/Origin/客户端令牌校验、操控页 3 秒心跳停止。

## 操作

1. 选择关节控制或 IK，以及左臂、右臂或双臂。关节目标使用标定零点和当前逻辑方向。点「填入当前位置」可按所选各臂把当前关节角填入 7 轴目标，再作调整。留空跳过该轴。IK 使用基座系毫米坐标，腕姿目标留空时沿用当前朝向。预览从多个初始关节姿态求解，在符合关节限位和位姿精度要求的解中选择离当前关节姿态最近的一组。搜索结束时若未找到解，页面显示“未找到收敛解”。离线模式支持 Aero 固定手指模型的指尖，实机 IK 使用 J7 手腕控制点。
2. 设定运动时间和额定速度百分比，预览目标。网页按各关节的标定角度范围规划，执行器根据本次起点和目标计算各轴行程。速度百分比是规划基准；若目标时间要求更高速度或加速度，按本次所需值放行并在预览中显示峰值，不再拒绝。实机路径不再做模型接触扫描。
3. 对照预览的角度和指令轴，单击执行。预览不再设 60 秒有效期；执行前仍以当前反馈重建轨迹，预览后的起姿漂移会被采纳。终点误差、跟踪误差、路径点偏差和周期迟到只记录为提示，不再中断执行或失能；执行结束进入“已到位 · 使能保持中”。同一页面可继续预览和执行已使能轴的新目标，其余已使能轴维持原目标。需要增加参与轴时，先停止，再选择全部使能。
4. 点击“停止并失能”，等待使能计数回到 0/14 后可以切换模式。操控页失联超过 3 秒、运行故障或服务正常关闭都会触发停止。实机停止会核对两臂失能回读，回读失败显示“停止未确认”。

### 调整腕部姿态

在「IK 控制」选「手腕」和要调整的臂，填写 Roll、Pitch、Yaw 后预览。也可先点「填入当前姿态」，再调整所需角度。三个角依次对应基座固定 X、Y、Z 轴，单位为度。填写任一腕姿角后，留空的 XYZ 和姿态分量沿用预览时的腕部反馈。只填腕姿角时，预览目标的 XYZ 沿用当时的位置。执行沿用关节插补。

## 实机多模式的接入条件

实机启动默认使用 `configs/openarm_position_mode.json` 的 `monitor_inventory` 指向本机 14 轴 C02 盘点，也可用 `--mode-inventory <inventory.json>` 显式指定。切换时核对固件与通道。缺少盘点时仍显示实际模式，模式写入按钮不可用。加载盘点后即可在失能状态切换四种寄存器模式。

四种模式都可直接“全部使能”、预览、执行和保持，不要求现场协议配置。目标帧按模式偏移发送（POS_VEL 为 `基础ID + 0x100`，VEL `+0x200`，POS_FORCE `+0x300`）；使能/失能的 `0xFF×7 + 0xFC/0xFD` 特殊帧默认发往基础电机 ID，与 OpenArm 官方 CAN 库 `create_enable_command` / `create_disable_command` 的实现一致。[现场盘点](../logs/openarm/mode_switch/20261119_171446/inventory.json)

现场若核实到某轴固件要求特殊帧使用模式偏移，可在启动时附加 `--drive-profile <现场协议配置.json>` 覆盖。未提供该文件时按基础 ID 与 10% 电流比例执行。配置使用 UTF-8 JSON，包含以下字段。

| 字段 | 内容 |
| --- | --- |
| `inventory` | 完整 C02 备份 JSON 的路径，可相对协议配置文件。程序检查映射、两臂通道、14 轴身份、寄存器和失能记录。 |
| `special_frame_address` | 对象含 `left`、`right` 两个数组，各按 J1～J7 填写经核实的 `base` 或 `mode`，分别指基础 ID 或模式偏移 ID。 |
| `disabled_preload_verified`、`volatile_mode_write_verified` | 两项均为布尔值。现场确认 14 轴能够在失能时预装当前目标、模式寄存器写入可易失生效后填 true。 |
| `pos_force_current_fraction` | 已核实适用于双臂的最大相电流比例，范围 0.0001～1。 |

加载盘点启动后，先在失能状态选择模式。服务核对各轴硬件、软件和子版本，逐轴写入需要变化的 CTRL_MODE，独立读取全部 14 轴后开放使能。部分写入失败时按原值回退已尝试的轴，页面保留故障并锁定执行。网页切换流程不发 Flash 保存命令。再次连接后应重新确认模式。运动起点仍会读取各轴固件与模式：与控制台选择不一致或读回失败只记 `mode_readback` 提示，不拒绝该次运动。

## 反馈与日志

- 关节表可切换角度、速度、力矩、温度与电机状态。手腕位置和腕部姿态由同一帧关节反馈经 V1 正运动学计算。「指音关系」按 A3/C4 实琴原位、腕部 Y 和固定指距估算白键。两行显示手指编号 `1 2 3 4 7 8 9 x` 与对应音名。反馈缺失或投影越出琴键范围时显示「—」。实琴指尖落点待逐指核对。
- 重要反馈区显示进度、到位、取消、故障和跟踪偏差。运动中的偏差逐周期记录，轨迹结束时记录终点误差并进入保持；偏差不再阻止到位。执行日志可按等级筛选，按事件、参数或指令编号搜索。
- “导出 JSONL”下载当前服务会话的完整日志，包含控制参数、逐周期目标、观测、偏差和停止回读。原始文件保存在 `logs/openarm/monitor`。每条记录带有 `mode`，同一条指令用 `request_id` 关联。
